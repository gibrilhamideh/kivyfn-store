# Release coverage matrix

This maps every coverage row in PLAN.md section 14 to assertions in the test
suite. It is an evidence map, not a claim that every combination has been
exercised. Read the last column before treating an area as exhaustive. A missing
focused case does not by itself demonstrate a runtime defect.

Actual command results and environment limitations belong in
[release-verification.md](release-verification.md). This document does not reuse
aggregate results from earlier implementation runs.

Most transport integration tests use the `transport_kind` fixture in
[tests/conftest.py](../tests/conftest.py), parameterized over Direct and Socket.IO.
Browser tests use the real Store/Host/Client process in
[frontend/tests/backend.py](../devtools/frontend/tests/backend.py), with separate
Direct and Socket.IO Playwright projects. Frontend model tests are unit tests;
they are not substitutes for the browser runs.

identity and membership notifications; instruction/signal order tests remain.
Final check results are in [release verification](release-verification.md).
